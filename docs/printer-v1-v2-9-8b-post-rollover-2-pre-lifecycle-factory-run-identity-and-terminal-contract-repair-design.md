## Identity contract

### Two distinct identities

| Identity | Owner | Shape / source | When present |
| --- | --- | --- | --- |
| `campaign_run_id` | campaign supervision / command | `{execution_id}-campaign-run` | always after campaign creation |
| `factory_run_id` | memory-factory run row | UUID pre-generated by coordinator; durable only after lifecycle entry | only after genuine lifecycle entry |

Generic `run_id` must not serve both roles at the coordinator retain boundary.

### Pre-lifecycle return contract

When `result.lifecycle_started is False`:

1. lifecycle payload may carry `campaign_run_id` (campaign identity);
2. lifecycle payload must **not** expose a factory-run identity;
3. lifecycle payload must **not** place the campaign-run ID in a field the
   coordinator retains as factory UUID;
4. first terminal cause (for example `SOURCE_VISIBILITY_SHORTAGE`) remains
   authoritative and immutable;
5. reconciliation, reporting, and acceptance treat
   `lifecycle_started=false` and `factory_run_id=None`.

### Lifecycle-started return contract

When `result.lifecycle_started is True`:

1. factory identity is the initialized UUID (retained via
   `factory_run_initialized` at durable insert and/or post-return retain);
2. post-return retain prefers explicit `factory_run_id`, then historical
   lifecycle `run_id` **only when it is not campaign-run shaped**;
3. equality against the initialized UUID remains fail-closed;
4. a real factory UUID mismatch still raises
   `initialized factory-run identity changed`.

## Control-flow repair

### Before (defective)

```text
result = owner.run_operational(...)
lifecycle = dict(result.lifecycle)
returned = lifecycle.get("run_id")          # campaign-run on shortage path
if returned:
    retain_factory_run_id(returned)         # raises identity-changed
if not result.lifecycle_started:            # never reached on shortage path
    return pre_lifecycle_finalize(...)
```

### After (repaired)

```text
result = owner.run_operational(...)
lifecycle = dict(result.lifecycle)

if not result.lifecycle_started:
    # Never retain factory identity from a pre-lifecycle return.
    # No factory_run_id exposure; preserve shortage/block cause.
    return pre_lifecycle_finalize(...)

returned = extract_factory_run_id(lifecycle)
  # factory_run_id preferred; run_id only if not campaign-run identity
if returned:
    retain_factory_run_id(returned)         # fail-closed equality retained
# continue lifecycle cleanup / reconcile / report with true lifecycle_started
```

### Failure terminalization lifecycle truth

Exception-path terminalization currently passes the pre-generated factory UUID
unconditionally and sets `lifecycle_started=bool(factory_run_id)`, which
inflates lifecycle reporting when no durable factory row exists.

Repair:

- track whether factory identity was actually retained after genuine lifecycle
  entry (`factory_run_initialized` success or post-return retain success);
- pass `factory_run_id` into failure terminalization only when retained;
- otherwise pass `factory_run_id=None` so `lifecycle_started` remains false
  unless durable lifecycle entry evidence exists.

## CLI exception envelope mutation honesty

On `OPERATIONAL_COMMAND_BLOCKED`:

| Mode / state | Mutation reporting |
| --- | --- |
| No campaign action identity created (preflight/status/etc.) | proven `database_writes=0`, `database_mutation_known=true` |
| Campaign action identity exists (`action_run_id` set) | do **not** hardcode `database_writes=0`; report `database_writes=null`, `database_mutation_known=false`, explicit unknown status |

Exact positive write totals remain success-path / allowlist-delta territory. The
exception envelope must not invent a zero write total after campaign creation.

## Focused proof plan (minimum)

Deterministic offline tests only. No provider contact, authoritative campaign,
wrapper execution, live DB mutation, new authorization, or 15m/1h/4h rerun.

1. Pre-lifecycle `SOURCE_VISIBILITY_SHORTAGE` terminates cleanly without identity exception.
2. Campaign-run ID is never retained as factory-run ID.
3. `lifecycle_started=False` is honored before any factory retain.
4. No factory run, slot, step, campaign window, or memory window is fabricated.
5. Shortage cause remains the first terminal cause.
6. Lifecycle reporting stays false.
7. Cleanup and lease release remain clean.
8. Genuine lifecycle entry retains the initialized factory UUID.
9. A real factory UUID mismatch still fails closed.
10. Exact offline public-composition success remains intact (existing harness as regression).
11. Exception reporting no longer falsely claims zero DB mutation when a campaign action identity exists.
12. Retrieval, decisions, positions, trades, audits, and PnL remain locked (static / zero-delta assertions in focused path).

## Money-usefulness contribution

Honest pre-lifecycle shortage terminals restore operator signal quality: a thin
market stops as shortage, not as a false factory-identity fault. That prevents
wasted repair cycles, preserves one-use authorization economics, and keeps the
path clear for a later readiness audit + new authorization only when the
identity contract is sound.

## Risks / blockers

1. Residual market supply shortage remains possible after this repair.
2. Historical lifecycle reports still use `run_id` for factory UUID after entry;
   extraction must keep that working while rejecting campaign-run shapes.
3. Exception envelopes still cannot always compute exact write totals without a
   heavier delta scan; unknown is preferred over a false zero.
4. No authorization may be created until the next readiness audit PASSes.
