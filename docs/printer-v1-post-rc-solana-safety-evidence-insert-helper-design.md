## Future Helper Responsibility

A future helper may be named:

`insert_solana_safety_evidence(...)`

This name is design-only. This document does not implement it.

The future helper may later be responsible for accepting already-governed, already-normalized Solana safety evidence and writing exactly one audit-visible safety evidence row when all insert guards pass.

The future helper may later:

- Accept already-governed normalized safety evidence.
- Validate Source Governor trace.
- Validate scheduler/operator collection boundary.
- Validate token, optional pair, snapshot, memory window, or evidence-window target.
- Validate freshness, source status, and data quality.
- Validate `paper_only_context`.
- Normalize categorical safety labels.
- Reject forbidden fields.
- Write one row to `printer_solana_safety_evidence`.
- Return an audit-oriented insert result.

The future helper must not be trade-oriented. It must not return BUY, SELL, HOLD, paper-position, retrieval-ready, PnL, score, rank, confidence, or weighted decision fields.

| `evidence_captured_at` | Required | Source evidence capture timestamp. |
| `freshness_label` | Required | `SAFETY_EVIDENCE_FRESH`, `SAFETY_EVIDENCE_ACCEPTABLE`, `SAFETY_EVIDENCE_STALE`, or `SAFETY_EVIDENCE_UNKNOWN`. |

## Required Validations

The future helper must reject the insert or mark the evidence ineligible for clean support when:

- `token_id` is missing.
- `snapshot_id` is missing.
- `paper_only_context` is false.
- `source_request_id` is missing.
- Both `source_response_id` and `source_failure_id` are missing.
- A successful source result lacks `source_response_id`.
- A failed source result lacks `source_failure_id`.
- `target_status` is `TARGET_MISMATCH` or `TARGET_UNKNOWN`.
- `freshness_label` is `SAFETY_EVIDENCE_STALE` or `SAFETY_EVIDENCE_UNKNOWN`.
- `source_status` is `FAILED`, `STALE`, or `CONFLICTING`.
- `data_quality_label` is `DIRTY_DATA`, `STALE_DATA`, `MISSING_CRITICAL_DATA`, `CONFLICTING_DATA`, or `DO_NOT_TRAIN`.
- Source trace is missing or inconsistent.
- Scheduler boundary is missing.
- Operator approval is missing during manual proof.
- `safety_context_label` is high-risk or blocked.
- Forbidden fields are present.

The helper should fail closed. If a required guard is unclear, the future implementation should return an audit-visible rejection instead of guessing.

## Failed, Stale, And Missing Behavior

Future behavior must preserve bad evidence honestly:

- Failed source evidence may be recorded only as audit-only evidence if a future implementation explicitly allows failed-evidence rows.
- Missing Source Governor trace blocks insert.
- Missing response/failure trace blocks insert.
- Stale evidence blocks clean eligibility.
- Target mismatch blocks clean eligibility.
- `SAFETY_UNKNOWN` remains unresolved.
- `SAFETY_CAUTION` cannot unlock clean memory alone.
- `SAFETY_BLOCKED`, `SAFETY_UNSAFE`, and `SAFETY_DO_NOT_USE_FOR_MEMORY` cannot be clean.
- Failed, stale, missing, mismatched, conflicting, and high-risk evidence must not enter retrieval.

If future implementation chooses to insert audit-only failed/stale/missing rows, the return shape must say that the row is audit-only and cannot support clean memory.

## Source Governor Boundary

The future helper must require existing governed source trace.

Rules:

- The helper must not create source request, response, or failure rows itself unless a future approved task explicitly changes that boundary.
- The helper must require `source_request_id`.
- The helper must require `source_response_id` for successful evidence.
- The helper must preserve `source_failure_id` when source collection fails.
- The helper must not hide source failures.
- The helper must not call external APIs.
- The helper must not call Solana RPC.
- The helper must not call GoPlus, RugCheck, Helius, Jupiter, or any other source.
- The helper must not be callable directly by the memory engine.
- The helper must not be callable directly by the retrieval engine.
- The helper must not be callable directly by the paper decision engine.
- The helper must not be callable directly by the paper position or monitor engine.
- The helper must not be callable directly by a PnL engine.

The only acceptable future caller is a Source Governor and Central Scheduler/operator-approved flow designed in a later task.

## Central Scheduler Boundary

Future safety evidence insertion must remain behind a bounded scheduler/operator boundary.

Rules:

- The helper must only be reachable through a future scheduled/operator-approved flow.
- Manual proof requires explicit operator approval.
- No direct CLI bypass is allowed unless a future bounded operator command is explicitly approved.
- No continuous loop is allowed.
- No source spam is allowed.
- No daemon, cron, Celery, APScheduler, or always-on service is allowed.
- No runtime expansion is allowed before roadmap approval.
- The scheduler job kind should remain within existing safety/liquidity refresh style boundaries unless a later approved task adds a narrower job kind.
- Safety collection must not compete with higher-priority token snapshots or paper-monitoring work.

## Return Shape

Future helper return shape should be audit-oriented:

| Field | Meaning |
| --- | --- |
| `inserted` | Whether a row was inserted. |
| `evidence_id` | Inserted evidence row id, or null. |
| `audit_status` | `INSERTED_AUDITABLE`, `REJECTED_GUARD_FAILED`, `AUDIT_ONLY_EVIDENCE`, or equivalent. |
| `clean_eligible` | Whether this safety evidence row can support the safety portion of a future clean-memory audit. This does not mean clean memory. |
| `rejection_reasons` | Guard failures, if any. |
| `source_trace_status` | `SOURCE_TRACE_PRESENT`, `SOURCE_TRACE_FAILED_VISIBLE`, or `SOURCE_TRACE_MISSING`. |
| `scheduler_boundary_status` | `SCHEDULER_BOUNDARY_PRESENT`, `OPERATOR_APPROVED_MANUAL_PROOF`, or missing/boundary failure label. |
| `downstream_unlocks` | Empty or all false. |

Required return constraints:

- `downstream_unlocks` must always be empty or false at this stage.
- `clean_eligible` means only "can support the safety portion if all other memory gates pass."
- `clean_eligible` does not mean clean memory.
- `inserted` does not mean retrieval-ready.
- `evidence_id` does not mean paper-decision-ready.
- Rejections must be audit-visible.

Example design-only return:

```text
inserted: false
evidence_id: null
audit_status: REJECTED_GUARD_FAILED
clean_eligible: false
rejection_reasons:
  - SOURCE_TRACE_MISSING
source_trace_status: SOURCE_TRACE_MISSING
scheduler_boundary_status: SCHEDULER_BOUNDARY_PRESENT
downstream_unlocks: {}
```

## Clean-Memory Gate Preservation

The insert helper alone cannot create clean memory.

Inserted safety evidence alone cannot unlock clean memory. It can only help resolve the safety portion of a future memory audit if the row is governed, fresh, target-matched, paper-only, complete enough, and categorically safe.

Other blockers still apply:

- market regime
- Solana chain heat
- flow direction
- flow pressure
- entry realism
- exit realism
- snapshot coverage
- evidence-window targeting
- source quality
- memory audit rules

Dirty, stale, failed, target-mismatched, conflicting, high-risk, and audit-only safety evidence cannot enter retrieval.

No paper decision, BUY, paper position, paper trade event, or PnL can be unlocked by the insert helper.
